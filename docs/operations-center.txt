商品运营中心：首版只读监测与广告授权（2026-10-08）

使用流程
1. 工作台 → 商品运营中心 → 刷新上架记录，将已有按货号保存的上架记录导入监测台账。
2. 选择店铺和货号，点击同步。首次同步读取商品当前状态、Ozon SKU、7/30 天指标及真实搜索词。
3. 查看任务进度和商品详情。未授权、无记录、统计延迟、配额等待与接口错误分别显示，不填为 0。
4. 在定时监测设置中开启每日同步。默认关闭；后台任务写入 SQLite，可在刷新页面和服务重启后恢复。
5. 广告模块单独授权，读取已有广告活动，选择活动和日期后生成官方异步报表。不会创建或激活广告。

广告授权所需
Ozon 卖家后台 → 设置（Настройки）→ API 密钥（API-ключи）→ Performance API。
创建服务账号，取得 client_id 和 client_secret。在运营中心广告授权表单填写；不要发到聊天里。
必须使用对应店铺的广告账号；这不是现有 Seller API 的 Client-ID / Api-Key。
授权只允许通过 HTTPS 或受信 SSH 隧道的本机地址提交。密钥加密保存，前端不回显，不存浏览器。
官方文档：https://docs.ozon.ru/api/performance/

数据口径
- 产品健康与库存在同步时读取；不能仅靠流量判定已开售或对目标买家可见。
- Seller 数据按店铺、货号、SKU、时间区间隔离。搜索词详情最多每 SKU 15 个词，部分指标需会员权限。
- 查询统计通常延迟 1–2 天；区间快照不按天累加。基本销量和流量读取能力分别按实际响应显示。
- 搜索/类目展示、商品卡展示不是互斥来源；不能加总，也不能用总流量减广告流量推算自然流量。
- 广告 CSV/ZIP 保留官方列及来源；币种、指标单位或归因口径不明确时不强行换算。
- 广告归因收入不是增量收入；无实际成本资料时不计算真实利润，也不自动判定应加预算。

技术栈
继续使用 Python / FastAPI / Uvicorn、原生 JavaScript / CSS、SQLite、腾讯云 CVM / Nginx / systemd。
新增 operations.sqlite3 运营台账、持久任务与配额；API 进程内只读 worker 处理队列，无新消息中间件依赖。
广告独立保险库使用 cryptography Fernet，元数据和异步报表状态写入 SQLite。
现有 1688 插件、商品创建流程、对象存储与员工手工关键词库不受影响；监测词不自动混入词库。

首版边界与下一阶段
本次不修改线上商品，不自动开广告、调整出价、价格或库存，不调用收费模型。
当前沿用共享工作台访问控制，浏览器词库身份不等于员工登录。员工账号、角色、店铺权限须在自动写入前补齐。
优化草稿与自动广告控制下一阶段实现：事实核验、前后版本、审批、预算/SKU 白名单、止损、冷却期、执行审计。
自动开启广告还需明确店铺、商品、日/周预算、出价上限及是否允许自动停用；提供广告密钥本身不等于花费授权。
