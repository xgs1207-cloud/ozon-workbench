# 商品编辑表单与证据自动填充

## 界面约定

按用户提供的 Ozon 商品创建页参考图设计，保留电脑端工作台导航。主区域用白底、宽输入框和明确的分区标题；右侧展示真实缺项和来源，不模拟 Ozon 内容评分。

- 色彩：白底 `#ffffff`、正文 `#111820`、边框 `#dce4f0`、辅助文字 `#708198`、操作蓝 `#1557e8`、采集来源绿 `#087f5b`。
- 字体：Microsoft YaHei / 系统字体；字段优先清晰易读，不增加装饰性标题。
- 布局：左侧商品信息、尺寸重量、图片、官方特征；右侧完整度、未完成项、证据说明。只验证 1280 与 1440 像素桌面宽度，不开展移动端适配。
- 商品信息与预览是实际编辑阶段，不将每个属性包装成独立大卡片。

## 自动填充边界

`GET /api/workbench/products/{id}/listing-autofill` 仅使用采集资料及有效官方缓存，不调用 AI、不请求商品写接口。可选 `POST` 在所选店铺与类目范围内，最多执行六次官方字典查值；重复查询优先缓存。结果先进入本地编辑草稿，正常保存接口继续校验官方属性类型、字典 ID、SKU 与类目绑定。

可以确认的依据包括：结构化商品属性、原始属性表、明确的规格选项、带单位与明确商品/包装范围的尺寸重量，以及已经人工确认的官方类目。旧采集因中文字段名不匹配而未整理的属性，从原始快照读取；新采集兼容 `name_cn/value_cn`。

不自动猜测：品牌缺失时的“无品牌”、认证、型号、条码、上架售价、划线价、未知包装尺寸；装箱数量不是单件包装数量；采购价不是售价；商品重量不冒充含包装重量。多规格存在冲突时，不将某一规格的属性用于全部规格。翻译别名必须有确定的语义且匹配唯一官方选项，否则保留待确认。

人工输入和明确清空优先于自动建议。保存的字段保留来源；客户端不能通过伪造来源将任意内容标为采集已确认。现代官方表单编译只接受已保存字段，不在后台额外填入不可见的字典默认值。

`GET/PUT /api/workbench/products/{id}/listing-details` 保存不完整资料草稿。尺寸重量必须是毫米/克的正整数，包装不得小于已知商品值；八项商品与包装数据完整后才同步给现有尺寸重量步骤。缺资料仍阻止最终发布。清空字段不会被旧确认文件或 AI 推测复活。

## 验证清单

| 用户行为 / 主张 | 验证路径 | 需要观察的状态 |
| --- | --- | --- |
| 清晰商品创建表单 | 进入真实隔离测试商品 | 首屏商品信息、编辑/预览、右侧缺项都可见 |
| 自动填入有依据资料 | 打开商品，确认类目，使用字典匹配 | 值与来源一致，不同规格颜色分别显示 |
| 人工输入不覆盖 | 改材质、属性、售价，导航离开再返回 | 未保存修改仍存在 |
| 人工清空不复活 | 清空自动字段、保存、刷新 | 空白仍保留，缺项正确 |
| 官方字典准确 | 搜索、选择、删除、加载下一页 | 原值与官方 ID 对应，伪造 ID 保存失败 |
| 不完整资料可保存 | 只填写两项尺寸后保存 | 草稿保留，无凭空补全的包装资料 |
| 商品信息→预览→返回 | 切换两阶段 | 预览使用当前草稿，修改值不丢失，不发上架请求 |
| 图片与文案原操作保留 | 看采集图/图位与文案编辑区域 | 来源图不被冒称已生成并质检的上架图 |
| 桌面视口 | 1440×1000、1280×900 | 无横向溢出，右侧栏与保存操作不遮挡字段 |
| 异常路径 | 无类目、字段冲突、非法单位、保存失败 | 给出可操作缺项提示，不生成虚假成功 |

禁止在生产商品上写入测试资料；浏览器完整交互在独立测试目录执行。生产环境仅验证页面及读取接口。

## 本次验证记录（2026-10-07）

- 本地全量 `python -m unittest discover -s tests -q`：928 项测试运行通过，其中 1 项按测试条件跳过。
- 隔离浏览器完成采集资料 → 自动匹配 → 保存 → 刷新闭环，核对了不同规格颜色、人工清空不重填、取消某一规格后保存，以及预览/导航保留手动草稿。
- 1280×900 与 1440×1000 桌面检查通过；隔离测试页面没有脚本错误或横向溢出。
- 额外验证了部分资料保存、旧确认字段迁移、文件写入及属性编译失败回滚、同一商品并行保存合并，以及官方属性持久化前重新检查提交状态和类目绑定。文件事务处理正常执行中的异常；不宣称多 JSON 文件在断电时具有数据库级原子性。

自动填充不替代最终人工审核；价格、条码、证书、缺失包装参数仍由卖家补充。复杂组合属性沿用已有只读提示，不通过猜测生成组合值。
