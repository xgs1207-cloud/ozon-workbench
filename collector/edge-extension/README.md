# 1688 / Ozon / Seerfar 采集 Edge 插件

从原项目 `jlcglobal/jlc-global-ozon-auto-listing` 复用，默认工作台地址为公网入口 `http://43.132.190.110:8088`（nginx 反向代理 + Basic Auth）。1688/Ozon 商品采集可沿用此入口；**Seerfar 市场报表因包含独立写入令牌，必须用 HTTPS 或本地 SSH 隧道**。

## 功能

- 在 1688 商品详情页一键采集：标题、供应商、SKU（含规格/采购价/SKU 图）、主图、详情图、详情页属性，以及当前商品已加载的视频资料。
- 1688 **全部规格、图库图、详情图直接入库**，不再先选 SKU / 类目。工作台里再选择上架规格（≤10 个）与真实 Ozon 类目；未选规格仍保留。
- 重复采集自动查重（同一 offer 已入库会提示，可选择建新版本）。
- 也支持采集 Ozon 参考页（竞品文案/图片），存到 `references/`。
- Seerfar 页面有独立 content script；在当前显示的报表列中采集，支持人工启动、最多 20 页的逐页入库与停止。

## Seerfar 报表采集到工作台

插件只读取你已登录的 Seerfar 页面里**当前显示的表格列**，不调用 Seerfar 付费 API。打开报表前，先在 Seerfar 勾选需要的指标列。单页最多读取 200 行；在弹窗中由你指定本次采集 1–20 页，插件会逐页等待表格更新、去重、上传，遇到分页结束、页面未更新或接口错误会停止并显示已入库数量。若页面上有多个分页器且无法确定报表所属分页器，插件会停止而不盲目点击。市场数据写入令牌是工作台单独配置的 `WORKBENCH_MARKET_INGEST_TOKEN`，**不是 Seerfar API Key**，请由管理员通过安全方式提供。

在 `https://www.seerfar.cn/admin/market`（以及 `.html` 形式）上，Seerfar 指标是**最近 30 天滚动窗口**。插件自动用本机时间生成采集月份 `YYYY-MM` 并发送 `period_kind=rolling_30d`；这个月份只是快照归档键，**不是自然月统计**。类目报表需手填其真实自然月；0.4.30 商品报表需按页面手动选择「最近 30 天」或「完整自然月」，不接受其他自定义口径。推荐同月只计一次滚动快照。

当前公网入口是 HTTP，插件会拒绝把市场数据令牌发送到那里。请先在本机保持 SSH 隧道运行：

```powershell
ssh -i "D:\AI作图\ozonfinancedeploy.pem" -N -L 8766:127.0.0.1:8766 ubuntu@43.132.190.110
```

若本机 8766 被占用，可把上面 `-L` 的**左侧**端口改为 8767，再把插件工作台地址相应设为 `http://127.0.0.1:8767`。在插件「工作台连接」填 `http://127.0.0.1:8766`（或实际映射端口），点「保存并连接」；打开并刷新 Seerfar HTTPS 报表页，先选好指标列，再打开插件、填写工作台写入令牌，点「验证并保存令牌」。只有工作台返回有效验证响应时，令牌才写入此浏览器的 `chrome.storage.local`；下次打开插件会自动回填，即使后续报表表格识别失败也不用重输。它不会同步到其他设备、不会写入代码或仓库，清除时点「清除本机令牌」。**本机持久保存并非加密**，浏览器配置文件被他人访问时令牌仍可能被读取，请只在私人电脑使用。卸载插件或点清除后，本机副本会删除；但服务端令牌并不会因此撤销。服务端仍会逐次校验令牌，不能取消校验。

选择最多采集页数后，点「采集当前及后续页」；开始采集前会再次验证令牌。**保持弹窗打开**，失焦关闭会中断本次逐页循环；已成功入库的页不会回滚，可从浏览器当前所在页继续。每页最多 200 行，必要时按小于 1 MB 的批次上传，重复行会跳过。真实页面验收记录见下文。

升级到 **0.4.34** 后，请到 `edge://extensions/` / `chrome://extensions/` 点击此已解压扩展的「重新加载」，并刷新已打开的 1688 商品页。若提示需要开发者模式，请在此测试/自用浏览器开启；不需要移除或重装插件，本机配置和令牌保留。HTTPS 自定义工作台地址会在「保存并连接」时请求该站点的访问权限。

### 1688 视频采集与提交后回读（0.4.34）

插件读取当前商品图库/详情区的播放器、开放 Shadow DOM、已加载 JSON 视频资料；对于页面已经请求的视频资源，仅在它能与当前商品播放器的 ID 或原视频地址明确匹配时补全，绝不把广告/推荐视频当商品视频。不会自动播放、不复制 Cookie、不主动请求视频。建议先正常打开商品视频，再点采集；暂未加载、blob、HLS/DASH 或受保护视频会明确显示原因，无法保存时可在后台上传有使用权的原 MP4/MOV。

采集只保存元数据和私有源地址；后台由你明确获取文件并确认使用权、视频标题和关联规格，再发布到对象存储。发布时核验实际视频时长、分辨率、文件哈希与匿名访问，重复视频按内容地址复用，不把 1688 临时地址直接交给 Ozon。普通视频使用 Ozon `complex_id=100001`、URL 属性 `21841`、标题属性 `21837`；静态封面图不是 Ozon 的短视频封面。

商品导入成功不等于视频处理或买家页播放成功。已提交卡片可点「只读回读」核对本店铺、本商品的实际视频复杂属性及商品处理状态；只读刷新不会再次提交，也不写库存。分别显示未选择、尚未读回/处理、接口已读到、转存候选但内容身份未证明、错误。即使接口已读到，仍需自行打开买家商品页确认播放。

本次用真实服务代码与模拟页面/COS/Ozon 响应覆盖闭环，不代表已对真实买家页视频做验收。接口依据与验收边界见 [视频闭环说明](../../docs/video-lifecycle.md)。通过工作台下载新的插件压缩包后解压，按上文重载和刷新；不要同时加载新旧两套扩展。

### 1688 全规格入库与页面兼容（0.4.32）

修复 `offerImgList` 补图逻辑把对象误当数组导致整次采集失败的问题，并支持新版 CSS 图库、商品详情开放 Shadow DOM、展开式规格行与规格专属图。页面接收脚本缺失时会检查并补载；仍运行早期脚本时提示刷新，不能叠加接收器。错误返回明确中文说明和 `is_collectable=false`，不再把失败信息当有效商品。

点击「采集当前商品」会提交 `collection_mode=all_skus`。后台保存全部规格原名、采购价、规格图与来源数据；不要求提前选类目，不默认选中任何规格，不调用 AI 或提交 Ozon。工作台自动打开该商品，可搜索规格、勾选并确认上架范围。当前单次上架范围仍为 1–10 个（本工作台的流程限制，不是 Ozon 平台 SKU 上限）；采集与上架数量限制分离，单链接防异常采集上限 2000 个，超限报错而不是截断。

缺价、缺失或重复标识等规格先保留并标为待核验，不猜值、不自动选择。相同图片 URL 在同次入库只下载一次；图库、规格图、详情图各自保留用途，重复规格图可引用同一本地文件。改选不会删掉原始规格，清除选择也不会自动恢复全量上架。重复采集仍需显式选择新版本，不覆盖旧商品。等待图片下载期间请保持插件弹窗打开；中途关闭或网络中断后，先在工作台确认是否已入库，避免盲目重采。

2026-10-07 对 `https://detail.1688.com/offer/1072823232979.html` 使用真实 0.4.32 插件实测：识别 52 张图库图、49 张详情图、56 个 SKU / 专属图和 24 个属性；通过采集按钮及显式新版本按钮保存全部 56 规格，未打开 SKU 抽屉。隔离工作台默认 0 个已选，56 规格均有本地图片引用；在后台搜索并确认绿色、紫色两个规格，其他 54 个规格完整保留。内容去重后落盘图库 51、规格图 46、详情图 46 张（不同用途独立保留）。未写生产库、未调用付费 AI 或 Ozon 写接口。

验收还覆盖：后台最多 10 个选择、空选择拦截、刷新后选择保留、未关联批次商品入口、重复采集的新版本确认。61 项 Node 测试、812 项 Python 测试与插件语法检查通过。按用户要求只以电脑端作为本次界面验收目标。

### 页面连接自恢复（0.4.31）

若安装或重载扩展后未刷新已打开的报表，旧版可能报 `Could not establish connection. Receiving end does not exist.`。这表示页面接收脚本缺失，**不是工作台写入令牌失效**。0.4.31 普通采集和后台联动均先检查页面连接，缺失时只在 Seerfar HTTPS 报表顶层页面补载 `seerfar-content.js`，确认就绪后再采集；不会刷新页面或清空你选择的指标、筛选条件。

补载可重复执行，不会注册多个接收器。若旧版接收器仍有效、网站访问权限被关闭、标签页关闭或登录失效，会提示相应中文处理方法。旧版接收器仍在时请手动刷新报表页，避免叠加两个翻页处理器。已发出的翻页指令一旦响应丢失不会自动重发，防止多翻一页；已入库数据保留，可确认当前页后重新开始或继续联动任务。

依据：[Chrome 内容脚本的程序化注入与隔离环境](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。此恢复仅加载插件自身脚本，不读取登录 Cookie，也不调用 Seerfar 付费 API。

2026-10-07 使用真实加载的 0.4.31 插件，在用户自行登录的 Seerfar Chromium 测试窗口重载扩展但不刷新报表，分别复现缺失接收器错误：商品页经弹窗按钮自动恢复后采集 2 页、40 行；类目页经联动开关和采集按钮自动恢复后完成 1 页类目、1 页对应关键词，共 40 行。均写入独立测试 SQLite，未写入生产库；令牌验证状态没有被页面连接错误覆盖。41 项 Node 回归测试及语法检查通过。

## 类目 → 对应关键词联动采集（0.4.30）

1. 在 Seerfar「热销类目」页面先筛选并查询出目标类目，显示需要的指标列。**联动采集依据当前筛选报表，不依据行勾选框**。
2. 在插件填写类目报表的实际自然月、类目报表最多页数。展开「类目 → 关键词自动采集」，勾选开关，设置每个类目的关键词页数和最多联动类目数（均 1–20）。默认最多 10 个类目、每个 3 页关键词。
3. 点「采集当前及后续页」。类目逐页入库后，从已采集行的真实 Seerfar 类目链接提取 ID，在独立标签页选择同 ID 类目并点击页面查询，然后采集关键词。ID 缺失会跳过并显示原因，绝不按中文名称猜测、也不回退到全部市场。
4. 此联动任务由后台运行，**可以关闭插件弹窗**；重开可查看进度、停止或在修复登录/连接问题后继续。浏览器和工作台连接仍需保持运行，采集标签页不要手动改筛选或翻页。普通单报表采集仍需保持弹窗打开。

每页上传保留原始字段及类目筛选 ID；关键词口径为最近 30 天，月份仅作快照归档。任务状态不包含工作台写入令牌；令牌仍从本机设置读取。中断后已入库数据不回滚，重试由数据库去重。进度中的新入库数是收到服务器确认的数量，极端断线时可能少计，但不会重复插入数据。

2026-10-07 已在用户自行登录、实际加载 0.4.30 插件的 Chromium 测试窗口完成后台联动：2 页类目、智能手机/夹克各 2 页关键词，共 6 页、120 行成功写入隔离 SQLite，任务状态 done。此前合成页面全流程测试也通过。真实页面操作没有调用开放付费 API；测试数据未写入生产数据库。选择器结构变化时会安全停止。

## Ozon 商品机会库

在 Seerfar 商品报表显示「商品 / SKU、类目、上架时间、销量、评论数、价格、评分、退货取消率」等列后采集。组合商品单元格中的可见 SKU 会提取为入库标识，原单元格内容保留。

工作台新增「商品机会库」，与 1688 商品批次分开；筛选完全在数据库内完成，不调用付费 API。商品卡按钮跳转到采集的 Ozon 商品链接，或由可核验数字 SKU 构造的官方商品页。

首版规则详见 `docs/product-opportunity-library.md`。采集前须在插件按商品页面实际口径选择统计周期，不要将滚动周期冒填为自然月。缺上架时间、竞争证据或过期销量等数据会进入「待核验」，不会被当作低竞争推荐。

- **工作台地址**填入带登录信息的完整地址：


- 点「保存并连接」→ 应显示「已连接共享工作台」。

地址（含密码）只保存在本机浏览器的 `chrome.storage.local`，不会同步、不进仓库。

## 采集 1688 商品

1. 浏览器打开 1688 商品详情页（`detail.1688.com/offer/<id>.html`），等页面完全加载（SKU 图都出来）。
   **升级旧插件后刷新（F5）一次。**
2. 点插件图标 → 确认标题、主图/SKU/详情图数量正常 → 点「采集当前商品」。
3. 插件把全部规格、属性、图库与详情图片 URL POST 到工作台；服务端下载图片并保留去重后的本地素材。等待成功前保持弹窗打开。
4. 成功后自动打开该商品审核页；在「选择上架规格」搜索并勾选要上架的 SKU，点击「确认所选 SKU」。也可从「1688 商品批次 → 已采集的 1688 商品」进入。
5. 再确认关键词、Ozon 官方类目与后续事实/文案/图片等，不会自动开始生成或发布。

## 工作原理（与本工作台的接口契约）

| 插件调用 | 工作台端点 | 说明 |
|---|---|---|
| 测试连接 | `GET /api/workbench/summary` | 返回商品数 / 就绪店铺数 |
| 采集前查重 | `GET /api/collector/duplicates?source_url=...` | 同一 offer 是否已入库 |
| 采集入库 | `POST /api/collector/products` | 载荷含 `collection_mode=all_skus` / `title_cn` / `main_images[]` / `detail_images[]` / 全部 `skus[]`；无须提前选类目 |
| 后台选规格 | `GET/POST /api/workbench/products/{id}/skus` | 返回规格名称/图片/采购价，选择结果与原始采集分开保存 |
| Ozon 参考页 | `POST /api/collector/ozon-reference-page` | 存到 `references/` |
| 打开操作台 | `GET /1688-collection` / `/ozon-reference` / `/command-center` | 303 跳转到 `/` |

请求头：`X-Factory-Device-Id`（区分设备）、`Authorization: Basic ...`（nginx 认证，来自地址里的用户信息）。

## 文件说明

- `manifest.json` — MV3 清单。
- `content.js` — 1688 / Ozon 页面采集 + SKU 抽屉 + 类目选择（核心，147KB）。
- `seerfar-content.js` — Seerfar 页面采集。
- `seerfar-bridge.js` — 弹窗与后台共用的页面就绪检查、缺失接收器补载与防重放传输。
- `product-bridge.js` — 1688 / Ozon 商品页面连接恢复、安全页面校验与旧脚本刷新提示。
- `tests/product-capture.test.cjs` / `tests/test_full_capture.py` — 页面数据形状、新版图片/规格、全规格入库和后台选择门禁回归。
- `tests/seerfar.test.cjs` — 无账号的表格、地址、授权与安全门槛回归测试（`npm test`）。`npm run build` 检查现有 JavaScript 语法；旧 `src/*.ts` 源码不在本仓库，未依赖 TypeScript 编译。
- `popup.html` / `popup.js` / `popup.css` — 插件弹窗 UI。
- `background.js` — service worker：代理 HTTP 请求（注入认证头、绕开混合内容限制）、打开操作台标签页。
- `page-probe.js` — 注入页面上下文读取 `window` 里的商品数据。
- `category-tree.zh-CN.json`（6MB）— Ozon 官方简体中文类目树缓存（选类目用）。
- `category-rules-cache.json`（24MB）— 类目属性规则缓存（选类目后加载必填属性）。

> 两个缓存 JSON 是静态数据；如果 Ozon 类目有大更新，可重新从原项目拉取或让工作台提供实时接口（插件会优先调接口，失败才回退到本地缓存）。
