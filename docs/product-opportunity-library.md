# 商品机会库与类目联动采集

商品机会库是已采集 Seerfar/Ozon 竞品的研究视图，底层复用市场数据库 `observations` 的 `products` 数据集，不创建重复副本，也不与 1688 上架商品混在一起。原始行、图片、链接及采集来源全部保留。

## 首版可解释规则

| 维度 | 判断 | 数据不足的处理 |
|---|---|---|
| 上架年龄 | 今日减原始上架日期；或采集时上架天数加已过去天数；严格 `<90` 天 | 待核验；未来/非法日期不猜测 |
| 有销量 | 来源报表销量 `>0`，第二行增长百分比不参与销量解析 | 缺失待核验；零销量排除 |
| 类目竞争 | 类目竞品数÷销量；相同统计口径、月份的已采集类目中位于较低 40% | 有效类目不足 5 个、缺竞品数/销量或快照超过 62 天，待核验 |
| 评价壁垒 | 评论数处于同类目、相同统计口径及月份商品样本较低 50% | 有效同类目商品不足 5 件或缺评论数，待核验；评论数不是竞争度 |
| 需求表现 | 同类目、同周期销量分位，用于机会分 | 不跨周期相加，不累计重复 SKU |
| 退货取消 | 0–100% 时仅作最多 8 分的扣分 | 缺失不当作零退货，不直接淘汰 |
| 数据新鲜度 | 商品快照不超过 14 天 | 老销量仍展示，但推荐先待核验 |

机会分 = 类目低竞争分 40% + 低评价壁垒分 30% + 同类目销量分 30% − 退货扣分。分位使用同值中位排名；过滤搜索词或分页不改变比较样本。推荐同时满足年龄/销量条件、竞争和评价门槛、完整证据以及机会分 ≥60；门槛是首版研究启发式，**并非 Ozon 官方规则或已证明有效的收益模型**。

每个 SKU 仅采用最新 Seerfar 快照，不把历史销量相加。状态分为「推荐研究 / 继续观察 / 待核验 / 不符合条件」。点击详情可查看全部判断依据和原始字段。

样本取决于用户选择的 Seerfar 筛选条件，可能偏向热销榜单；结果不能外推为全市场低竞争，更不能证明物流、采购成本、广告费用或利润可行。用户履约路径是中国直发，退货取消率仅扣分；没有增加物流硬淘汰门槛。

## 接口与安全

`GET /api/research/product-opportunities` 支持 `q、category_key、status、limit、offset`，只读、无外部 API 调用，响应禁止缓存。与原始报表接口一样由公开工作台的 nginx 登录保护，FastAPI 只绑定服务器 loopback；不把写入令牌交给前端。

跳转链接仅接受 HTTPS 的 `ozon.ru` / `www.ozon.ru` 商品路径。没有有效链接时，仅对 5–20 位数字 SKU 构造官方商品地址；不保证商品未下架或没有地区限制。

## 类目联动

插件 0.4.30 的联动开关默认关闭，由用户主动启动。采集当前筛选后的类目表，最多 20 页；提取真实类目链接中的 ID，最多联动 20 类目，每类最多 20 页关键词。缺真实 ID 不猜名称、不查询全部市场。关键词页通过正常类目选择器和查询按钮操作，逐页只读取页面当前显示的列，不提取 Seerfar Cookie/令牌，不调用或绕过付费 API。

后台状态保存在本机插件设置，可停止/继续。任务在新关键词标签页运行，保留类目标签页；关闭弹窗不中断。页面筛选变化、登录失效、异常分页或连接中断会停止并保留已入库数据。继续前须恢复登录及原工作台连接。

## 验证边界

自动规则、只读接口、排序、分页、手机端展示与真实 Chromium 扩展后台上传使用隔离数据验证（6 页联动、55 个界面商品样本，测试数据未写入生产数据库）。

2026-10-07 用户自行登录后，又在真实 Chrome 页面注入同版脚本，核验生产 Vue 类目组件、智能手机/夹克两个真实类目各 2 页关键词、类目和商品报表 1→2 翻页。真实商品字段是「商品信息 / SKU、售价、销量、评论数、评分、上架时间」，日期包含 `YYYY-MM-DD` 和另行展示的相对年龄；SKU 为商品单元格中独立数字行。

随后保留用户的测试浏览器登录状态，实际加载 0.4.30 插件，在真实 Seerfar 页面运行完整后台联动：2 页类目、智能手机/夹克各 2 页关键词，共 6 页、120 行全部成功写入隔离 SQLite，任务状态 done。10 行无真实跳转 ID 的类目按规则跳过联动；两个目标类目根据最大联动数按顺序选取。未调用开放付费 API，未把测试数据写入生产数据库。升级时需重新加载扩展、刷新页面；结构变化会安全停止。
